# Changelog Policy

LexiChess keeps a human-readable changelog in `CHANGELOG.md`.

## What To Record

- user-visible feature additions
- bug fixes that change behavior
- breaking changes
- important documentation and workflow changes
- release dates and version numbers

## What To Avoid

- internal noise with no user or contributor impact
- repeating commit messages without context
- massive undifferentiated lists of file edits

## Entry Style

Each release entry should group changes into clear sections such as:

- Added
- Changed
- Fixed
- Removed

## Release Flow

Before tagging a release:

1. Update `CHANGELOG.md`.
2. Confirm the version number in the release plan.
3. Link any migration or rollout notes when needed.
